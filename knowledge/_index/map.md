# 왜 사슬 — 사실 → 원리 → 상황 → 사례 (렌즈는 가리키는 원리 아래)

아래로 갈수록 구체적이다. 위로 올라가면 "왜"의 답이 나온다.

- `FA-001` 알아보기는 떠올리기보다 쉽다 — 단서가 눈앞에 있으면 기억은 더 빨리, 더 자주 맞게 꺼내진다. (사실)
  - `PR-001` 떠올리게 하지 말고, 보고 고르게 한다 — 사용자가 기억에서 꺼내야 하는 것을 화면이 대신 보여 준다. (원리)
    - `LN-001` 입력·편집 화면을 볼 때 — 입력 화면은 '끝내는 조건 → 틀리기 쉬운 칸 → 저장 뒤' 순서로 본다. (렌즈)
    - `LN-005` 작업 공간을 볼 때 — 작업 공간은 '결과물 → 지금 상태 → 자주 하는 조작 → 되돌리기' 순서로 본다. (렌즈)
    - `LN-007` 설정을 볼 때 — 설정은 '기본값의 이유 → 묶음 이름 → 적용 시점 → 잃는 옵션' 순서로 본다. (렌즈)
    - `LN-008` 단계 진행을 볼 때 — 단계 진행은 '나눈 까닭 → 지금 위치 → 앞 단계의 값 → 되돌림 → 확정' 순서로 본다. (렌즈)
    - `ST-001` 정해진 값은 치게 하지 않고 고르게 한다 — 후보가 정해져 있는 칸에서는 사용자가 값을 외워 치지 않고 보고 고른다. (상황)
    - `ST-006` 입력 칸의 이름은 늘 보인다 — 칸이 무엇을 묻는지는 치는 중에도, 친 뒤에도 보인다. (상황)
    - `ST-011` 로그인 · 인증 칸은 붙여넣기와 관리자를 막지 않는다 — 인증 번호와 비밀번호는 붙여넣고 자동으로 채울 수 있다. (상황)
    - `ST-014` 긴 값은 줄이되, 전체를 보는 길을 남긴다 — 넘치는 값은 말줄임으로 줄이고 전체를 볼 길을 둔다. 뜻이 핵심인 글은 자르지 않는다. (상황)
    - `ST-033` 아이콘만 있는 버튼에는 이름이 있다 — 그림만 보이는 버튼도 읽어 주는 이름과 풍선 설명을 가진다. (상황)
