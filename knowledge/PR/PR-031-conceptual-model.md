## 카드

- 주장: 사용자는 시스템이 어떻게 움직이는지 모형을 세우고 그것으로 행동한다 (FA-015). 화면은 그 모형이 맞게 서도록 시스템의 움직임(무엇이 저장되고 · 어디로 가고 · 언제 반영되는지)을 드러내야 한다.
- 적용되는 때: 보이지 않는 처리가 있다 (자동 저장 · 동기화 · 학습 · 예약) · 상태가 여러 개다 (편집 중 · 저장됨 · 게시됨) · 사용자가 시스템이 한 일을 놀라워한다 · 같은 실수가 여러 사람에게서 나온다.
- 약해지는 때: 내부 동작을 몰라도 일이 끝나고 틀릴 일이 없을 때 (드러낼 필요가 없다) · 이미 익숙한 비유를 그대로 따르면 될 때 (따로 그릴 것 없이 관례를 따른다, PR-008).
- 요구로 바꾸면: 보이지 않는 처리가 있으면 그 처리가 있다는 것과 지금 어디까지 왔는지 보인다 · 상태가 여럿이면 지금 상태가 무엇이고 다음에 무엇이 되는지 보인다 · 하나의 일관된 비유를 쓴다.
- 확인 질문: 사용자가 "지금 저장됐나 · 반영됐나 · 다른 사람에게 보이나"를 화면만 보고 답할 수 있나. 시스템이 사용자 모르게 하는 일이 있나. 한 화면 안에서 비유가 섞이나.

## 강의

### 왜 그런가

사용자는 설명서를 읽고 모형을 세우지 않는다. 화면을 쓰면서 세운다. 그래서 노먼은 디자이너가 사용자에게 직접 말할 수 없고, 화면이라는 모습을 통해서만 말한다고 보았다. 그 모습이 시스템의 움직임을 제대로 드러내면 사용자의 모형이 맞게 서고, 그렇지 않으면 사용자는 자기 나름의 모형을 지어낸다. 지어낸 모형은 대개 다른 서비스에서 빌려 온 것이라, 이 시스템과 어긋날 때 틀림이 생긴다.

고치는 길은 둘이다. 시스템을 사용자가 이미 가진 모형에 맞추거나, 화면이 시스템의 움직임을 드러내 사용자의 모형을 고치게 하거나. 앞쪽이 싸고, 뒤쪽은 앞쪽이 안 될 때 쓴다.

### 흔한 오해

"내부를 다 보여 주라"는 뜻이 아니다. 보여 줄 것은 사용자의 결정에 영향을 주는 움직임뿐이다. 저장 방식이 결정에 영향을 주면 보이고, 서버 구조는 보이지 않는다.

또 하나. 비유(폴더 · 장바구니 · 휴지통)는 모형을 빨리 세우게 하지만, 비유가 시스템과 어긋나는 곳에서는 오히려 틀린 모형을 심는다. 휴지통에 넣었는데 바로 사라진다면 비유가 사용자를 속인 것이다.

### 복잡한 화면에서

AI가 만드는 결과물, 학습처럼 오래 걸리는 처리, 여러 사람이 함께 고치는 문서는 모형이 쉽게 어긋난다. '지금 무엇이 진행 중이고, 언제 끝나고, 끝나면 어디에 나오는가'를 화면이 늘 들고 있어야 한다 (PR-009 · PR-011). 상태 이름이 화면마다 다르면 모형이 둘로 갈라진다 (PR-018).
