## 카드

- 주장: 사용자는 화면이 자기가 한 일에 반응한다고 느낄 때 믿고 쓴다. 시키지 않은 일이 일어나거나 익숙한 동작이 갑자기 바뀌면, 무엇이 일어났는지 따라잡느라 멈추고 다시 확인한다.
- 적용되는 때: 자동으로 넘어가는 내용 · 자동 정렬 · 추천이 끼어드는 화면 · 업데이트로 동작이 바뀔 때 · 매일 같은 일을 하는 숙련자.
- 약해지는 때: 사용자가 맡긴 일(자동 저장 · 예약 실행)은 시스템이 해 주는 것이 주도를 지키는 것이다 · 처음 쓰는 사람에게는 안내가 이끄는 편이 낫다 (TN-007) · 안전이나 보안 때문에 시스템이 멈춰 세워야 하는 순간.
- 요구로 바꾸면: 사용자가 시키지 않은 큰 변화는 일어나기 전에 알리고 멈출 수 있다 · 시스템이 대신 한 일은 무엇을 했는지 보이고 되돌릴 수 있다 · 익숙한 동작은 예고 없이 바뀌지 않는다.
- 확인 질문: 사용자가 손대지 않았는데 화면이 바뀌는 곳이 있나. 있다면 그 바뀜을 멈추거나 되돌리는 길이 보이나.

## 강의

### 왜 그런가

사람은 화면이 어떻게 움직이는지 머릿속에 그림을 그리고, 그 그림대로 다음 행동을 한다. 시스템이 몰래 상태를 바꾸면 그림과 실제가 어긋난다. 어긋난 그림으로 한 행동은 모르고 틀리는 실수(오판)가 된다 (FA-010). 예상하지 못한 움직임은 하던 일의 흐름도 끊는다. 반응이 늦을 때 생각이 끊기듯, 예상 밖의 반응도 주의를 빼앗는다 (FA-008).

원문은 이 원리를 숙련자 쪽에서 설명한다. 숙련자일수록 자기가 화면을 다룬다는 느낌을 원하고, 놀라움이나 익숙한 동작의 변화, 지루하게 길게 입력하는 일, 필요한 정보를 얻기 어려운 일, 원하는 결과를 못 내는 일을 싫어한다.

### 흔한 오해

"사용자가 주도한다"는 자동화를 하지 말라는 말이 아니다. 사용자가 맡긴 범위 안에서 시스템이 알아서 하는 것은 주도를 돕는다. 자동 저장은 사용자가 "잃고 싶지 않다"고 맡긴 일이다. 문제는 맡기지 않은 일을 하거나, 한 일을 숨기는 것이다.

닐슨 3번 '사용자에게 통제와 자유를'과 가깝지만 강조점이 다르다. 닐슨 3번은 잘못 들어간 곳에서 나오는 비상구에 무게를 두고, 이 원리는 처음부터 사용자가 시킨 일만 일어나게 하는 데 무게를 둔다.

### 복잡한 화면에서

AI가 결과를 만들거나 고치는 화면에서 이 원리가 가장 자주 시험받는다. AI가 내놓은 것은 사용자가 받아들이기 전까지 제안으로 남아야 한다. 받아들이기 전에 원본을 덮어쓰면, 사용자는 무엇이 자기 것이고 무엇이 AI의 것인지 잃는다 (ST-005).

자동으로 넘어가는 내용은 멈출 수 있어야 한다 (ST-026). 정렬이나 추천이 사용자가 보던 자리를 밀어내면, 사용자가 누르려던 순간 다른 것이 눌린다. 알림은 하던 일을 가로채지 않고 옆에서 기다린다. 이런 곳마다 질문은 같다. 사용자가 시킨 일인가, 시스템이 끼어든 일인가.
