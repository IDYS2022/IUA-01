# IUA에게 맡기는 법

IUA는 맥락 카드를 받아 설계 요구서(그리기 전) 또는 진단서(그린 뒤)를 돌려준다. 부품과 값은 정하지 않는다. 그것은 그리는 쪽과 디자인 시스템의 일이다.

## 언제 부르나

| 난이도 | 이런 요청 | 부르나 |
|---|---|---|
| 쉬움 | 맥락이 요청에 다 있다 ("이 버튼 크게") | 부르지 않는다 |
| 보통 | 화면은 있고 목적은 짐작해야 한다 | 부른다. 짧은 요구서가 온다 |
| 어려움 | 새 화면 · 해석이 갈림 · 얽힌 것이 많은 화면 | 부른다. 전체 분석 |

## 순서

1. **맥락 카드를 채운다.** 칸과 본보기는 `${CLAUDE_PLUGIN_ROOT}/protocol/README.md`의 '받는 것'. 필수는 일 · M1 · M2 · 유형 (사후 진단이면 화면도). 모르는 칸은 `모름`, 짐작은 `가정:`.
2. **IUA를 부른다.** Agent 도구에 `subagent_type: "iua:iua"`, prompt에 맥락 카드 전체.
3. **돌아온 것을 읽는다.**
   - 되묻기가 오면: 사람이나 기획서에서 답을 찾아 카드에 채우고 한 번 더 부른다. 답을 못 구하면 `가정:`을 붙여 다시 부른다.
   - 설계 요구서가 오면: 그대로 그리는 쪽에 넘긴다. 요구를 고쳐 쓰지 않는다.
   - 진단서가 오면: '막힘'부터 고친다.
4. **그린 뒤**: 그리는 쪽은 요구마다 "어떻게 풀었나"를 보고에 적는다. 디자인 시스템으로 풀 수 없는 요구는 '결정할 것'에 올린다. 검수가 필요하면 화면과 요구서를 넣어 '사후 진단'으로 다시 부른다.

## 하지 않는 것

- IUA에게 부품 이름이나 크기 · 색 값을 묻지 않는다. 그것은 부르는 쪽의 디자인 시스템이 답한다.
- 부르는 쪽의 결정 기록(사람의 취향 · 프로덕트 판단)이 IUA의 요구와 어긋나면 기록이 이긴다. 어긋난 곳을 사람에게 알린다.
